---
name: Visitor matrix table single-header variant
description: How the shared VisitorMatrixTable component supports a spreadsheet-style single-header layout, and how to roll it out to more screens.
---

`components/shared/VisitorMatrixTable.tsx` supports a `variant` prop: `"card"` (default, original behavior — each row repeats its own column labels) and `"matrix"` (one header row shared by every data row below it, with the Visitor Name column frozen on the leading edge and every other column scrolling horizontally together in one synced ScrollView).

**Why:** the component is reused by four Receptionist screens (WalkInVisitorsScreen, AllVisitorsTodayScreen, AllVisitorsScreen, ReceptionistDashboardScreen). The user asked for the spreadsheet-style single-header look first on the dashboard, with an explicit plan to extend it to other screens later — so the fix had to be opt-in per screen rather than a global rewrite that would have changed all four at once. All matrix-variant columns share identical cell styling (no bold/icon/dot treatment on any one column) — an earlier version special-cased the name cell and the user flagged the inconsistency.

**How to apply:** to adopt the matrix look on another screen already using `VisitorMatrixTable`, just pass `variant="matrix"` on that screen's call site — no new component needed. Current matrix columns, in order: Visitor Name (frozen, bold), Schedule Time (combined "start to end" range, not separate Planned In/Out columns — matches the "Scheduled Time" language used elsewhere like VisitorRequestCard), Actual In, Actual Out, Company, Requested By, optional Purpose, optional Contact (email/phone, shown only if some row has one), Additional Services, Status/Actions. Optional columns only render if at least one visitor in the current dataset has that field, so column count stays consistent across all rows in a given table instance.

The component also supports approve/reject actions (`showApproveReject` + `onApprove`/`onReject`/`approveLoadingId`/`rejectLoadingId`, with a per-item `isExpired` flag showing an expired banner instead of buttons) and bulk-selection mode (`isSelectionMode`/`selectedIds`/`onToggleSelection`/`onLongPressRow` — tapping a row toggles selection instead of navigating while active). All 7 screens with a visitor list/table view now use `variant="matrix"`: ReceptionistDashboardScreen, AllVisitorsScreen, WalkInVisitorsScreen, AllVisitorsTodayScreen, UpcomingVisitorsListScreen (Receptionist), VisitorRequestsScreen (Employee/Manager "My Requests", shared via `userRole` prop), ManagerAllRequestsScreen ("All Requests", with approve/reject), ManagerDashboardScreen ("Pending Approvals", with approve/reject + selection mode). The old per-row-header components (`ApprovalRequestListRow`, inline `ApprovalTableRow`, inline `VisitorRequestTableRow`) were deleted after conversion — no screens remain on the old layout.

When a screen paginates with `onEndReached` (infinite scroll) and also needs the single self-contained matrix table (which renders all its own rows), don't feed the paginated items as FlatList `data` with one row per item — instead give the FlatList `data={[]}` / `renderItem={() => null}` and put the whole `<VisitorMatrixTable>` (fed the full array) inside `ListHeaderComponent`; pagination props (`onEndReached`, `ListFooterComponent`) stay on the outer FlatList untouched. Group-by-date screens nest one `VisitorMatrixTable` per date group inside that same header instead.

For non-visitor domains whose data doesn't fit the visitor-specific columns (e.g. BuffetAllRequestsScreen, where the "visitor" is really the requesting host and the record has no company/actual-in-out/services fields), pass `columns="simple"` — this swaps the scrollable columns down to just Location + Status/Actions, keeping the frozen name column and overall matrix chrome. Also available generically: `nameColumnLabel` overrides the frozen column's header (e.g. "Requested By" instead of "Visitor Name"), and `visitorSubtitle` on a `VisitorMatrixItem` renders a small caption line under the name (used for the host's department). `location` is a plain optional field on `VisitorMatrixItem` for the simple-columns Location cell.
