Prompt 1 — Web Frontend Team
Context
We are adding two features to the existing React web app:

Outlook Add-in — a lightweight task pane that appears inside Outlook and lets users open the web app to create a visit request, with visitor details pre-filled from the selected email.
Deep link pre-fill — the new request form accepts URL query params to auto-populate visitor fields.
Calendar sync badge — the request detail page shows whether the visit has been synced to Outlook calendar.
Well-known file serving — two static JSON files must be served for mobile deep link verification.
The backend already handles calendar sync (create/update/cancel). The frontend just needs to display the sync status and serve the verification files.

Feature 1 — Pre-fill New Request Form from URL Query Params
What to do
On the new visit request form (whatever route /requests/new or equivalent maps to), read the following query params from the URL on mount and pre-populate the corresponding visitor fields:

Query param	Field to pre-fill
name	Visitor full name
email	Visitor email address
company	Visitor company
phone	Visitor phone number
Rules
Pre-fill is optional — if params are absent, the form behaves exactly as today.
Pre-filled values should be editable by the user — do not lock them.
If an email param is present and passes basic format validation, mark the email field as pre-filled (no special UI needed, just populate).
Clear the URL query params from the browser address bar after reading them (use replaceState) so users don't accidentally share a pre-filled link.
Example URL
https://your-app.com/requests/new?name=John%20Smith&email=john@company.com&company=Acme

Feature 2 — Calendar Sync Status Badge on Request Detail Page
What to do
The backend will return a new boolean field calendarSynced on the request detail API response. Display a subtle status indicator on the request detail page based on this value.

Display rules
calendarSynced value	Status shown	When it appears
true	📅 Synced to Outlook (green/muted)	After visitor accepts
false or absent	Nothing shown	Before visitor accepts
Request cancelled + calendarSynced was true	📅 Calendar event cancelled (muted grey)	After cancellation
UI guidelines
Place it near the visit date/time section, not in the header.
Keep it subtle — small text with an icon, not a prominent alert.
It is read-only — no click action required.
The cancelled state only needs to render if the request status is cancelled and calendarSynced is present.
API contract to expect from backend
// GET /api/v1/visits/:id response will include:
{
  // ... existing fields ...
  calendarSynced: boolean;      // true once Outlook event created
  calendarEventId?: string;     // Outlook event ID (optional, may be omitted from response)
}

taskpane.js
const APP_URL = 'https://YOUR_DOMAIN'; // replace with actual domain
Office.onReady(() => {
  document.getElementById('openBtn').addEventListener('click', openRequestForm);
});
function openRequestForm() {
  const item = Office.context.mailbox.item;
  if (!item) {
    document.getElementById('status').textContent = 'Could not read email details.';
    return;
  }
  const params = new URLSearchParams();
  const from = item.from;
  if (from) {
    if (from.displayName) params.set('name', from.displayName);
    if (from.emailAddress) params.set('email', from.emailAddress);
  }
  const url = `${APP_URL}/requests/new?${params.toString()}`;
  // Opens in default browser — works in Outlook Desktop and OWA
  Office.context.ui.openBrowserWindow(url);
}
