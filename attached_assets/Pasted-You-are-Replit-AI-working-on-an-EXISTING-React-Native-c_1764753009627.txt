2) AXIOS HTTP CLIENT & ERROR HANDLING
==================================================

2.1) Axios client

Implement src/api/httpClient.ts using axios:

- Create a single Axios instance with:
  - baseURL from env (e.g. process.env.API_BASE_URL or some config file)
  - timeout (e.g. 15–30s)
  - default headers: Accept: application/json

- Request interceptor:
  - Read the current auth token from the existing auth context/store or secure storage.
  - If present, set Authorization: Bearer <token>.
  - Support abort/cancellation via Axios CancelToken if needed.

- Response interceptor:
  - On success, just return response.data (or whole response if needed).
  - On error, normalize into a custom ApiError (see below) and throw that.

2.2) Standardized error type

In src/api/errors.ts define:

- type ApiErrorCode =
    | 'UNAUTHORIZED'
    | 'FORBIDDEN'
    | 'NOT_FOUND'
    | 'VALIDATION_ERROR'
    | 'CONFLICT'
    | 'SERVER_ERROR'
    | 'NETWORK_ERROR'
    | 'UNKNOWN';

- interface ApiError {
    code: ApiErrorCode;
    status?: number;
    message: string;
    details?: any; // validation issues, backend error payload, etc.
  }

- A helper mapAxiosErrorToApiError(error): ApiError that:
  - Inspects AxiosError.response.status and response.data.
  - Maps:
    - 400/422 → VALIDATION_ERROR
    - 401 → UNAUTHORIZED
    - 403 → FORBIDDEN
    - 404 → NOT_FOUND
    - 409 → CONFLICT
    - 5xx → SERVER_ERROR
  - Network/timeout → NETWORK_ERROR
  - Fallback → UNKNOWN

- The Axios response interceptor should:
  - For any error, transform it using mapAxiosErrorToApiError and throw ApiError.

2.3) Standard API response handling

- If API responses are wrapped (e.g. { data, meta, error }), add a helper:
  - normalizeApiResponse<T>(raw): { data: T; meta?: Meta }
- If responses are plain JSON entities, keep helpers minimal.
